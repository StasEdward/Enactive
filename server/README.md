# Enactive Remote — server preview

Самостоятельный backend шлюза и адаптивная веб-панель. Исходники находятся в `server`, не подключены к основной solution и не зависят от проектов desktop. ASP.NET Core / .NET 10, SQLite без ORM, обычные HTML/CSS/JavaScript без frontend-фреймворка и сборщика. Namespace — `Enactive.Server`.

## Что работает

- Вход единственного владельца по настроенному приватному ключу; HttpOnly-cookie, CSRF, ограничение попыток входа, выход и отзыв сессий сменой ключа.
- Регистрация компьютера с одноразовым показом отдельного device token. В базе хранится SHA-256 токена. Отзыв закрывает активные соединения и запрещает новые.
- Исходящее соединение Host к `/hubs/host` через SignalR. Workspace публикуются самим Host.
- Создание черновика, постановка запуска в очередь, повторный запуск после окончания, запрос отмены.
- Постоянная очередь команд с ID, дедупликацией и подтверждением приёма Host.
- Полные запросы разрешений; ответы allow/deny; защита от второго ответа; отдельное подтверждение применения решения со стороны Host.
- Сохраняемые события, состояние запусков, результат и внутренний Inbox.
- Поиск и фильтры задач, карточки разрешений, компьютеров, история, тёмная/светлая темы и мобильная компоновка.

Интерфейс обновляет состояние раз в три секунды. SignalR используется для Host; подключение Host выполняет Sync раз в 15 секунд, поэтому доставка новой команды занимает до этого интервала. Данные не симулируются в пользовательском интерфейсе.

## Локальный запуск (Windows)

Из папки `server`:

```powershell
./scripts/dev.ps1
```

Скрипт собирает и запускает приложение на `http://127.0.0.1:5187`, генерирует локальный ключ владельца в `data/dev-owner-key.txt`. Введите содержимое этого файла на странице входа. `data/` исключён из Git. Порт можно поменять: `./scripts/dev.ps1 -Port 5190`.

Для запуска без скрипта задайте переменные окружения и выполните:

```powershell
$env:ENACTIVE_OWNER_KEY = '<random private value, at least 24 characters>'
$env:ASPNETCORE_ENVIRONMENT = 'Development'
dotnet run --project Enactive.Server.csproj -- --urls http://127.0.0.1:5187
```

Не используйте пример из документации как реальный ключ. Скрипт создаёт случайное значение. Development предназначен только для локального HTTP; не публикуйте его в интернет.

На пустой установке сначала зарегистрируйте компьютер в Computers. Сохраните выданный токен в конфигурации будущего Host. До его подключения и публикации workspace создание задачи недоступно — приложение объясняет следующий шаг.

## Бренд и перенос

В `wwwroot/brand` включены копии официальных `brand/brand.css`, Loop и контурных wordmark. Цвета компонентов используют брендовые CSS-переменные. Space Grotesk 500/700, Inter 400/500/600 и JetBrains Mono 400 лежат локально в `wwwroot/fonts`, вместе с лицензиями. CDN не нужны. Насыщенный Ember используется для основных действий; отказ и отзыв используют danger.

Шрифты и ассеты уже включены, npm для обычного запуска и publish не требуется. Чтобы обновить их из исходного бренда и зафиксированных пакетов:

```powershell
npm ci --ignore-scripts
npm run assets
```

Только скрипт синхронизации ассетов читает соседний `../brand`. При переносе измените его путь или оставьте включённые файлы. Сам сервер не зависит от родительского каталога и задаёт net10.0/nullable/implicit usings в собственном csproj.

## Проверки

Нужны .NET 10 SDK и Node.js 22+:

```powershell
dotnet build Enactive.Server.csproj
node --test tests/gateway.test.mjs
```

Тест запускает настоящий Kestrel на свободном loopback-порту, использует изолированную SQLite-базу в игнорируемом `test-results/`, входит через cookie/CSRF и подключает два SignalR-клиента. Проверяет аутентификацию, изоляцию Host, дедупликацию, полное содержимое разрешения, конкуренцию ответов, подтверждение Host, результат, перезапуск и отзыв устройства. Тестовые процессы завершаются автоматически.

`tests/host-client.mjs` — ограниченный локальный тестовый клиент протокола, не производственный Host. Он не исполняет shell-команды и не читает workspace. Для реального Host следует использовать `Microsoft.AspNetCore.SignalR.Client` и постоянные локальные inbox/outbox.

## Конфигурация и хранение

### Ubuntu 24.04 и Cloudflare Tunnel

Соберите `dotnet publish server/Enactive.Server.csproj -c Release -r linux-x64 --self-contained true -o artifacts/server-linux-x64` из корня репозитория. Перенесите содержимое публикации в `app/` рядом с `scripts/install-ubuntu.sh` на Ubuntu и выполните `sudo bash install-ubuntu.sh`. Скрипт предназначен для первой установки: существующую службу или `/opt/enactive-server` он не перезаписывает.

Установка создаёт службу `enactive-server`, пользователя без входа, данные в `/var/lib/enactive-server` и случайный ключ в `/etc/enactive-server/server.env` (доступен root). Устанавливает `cloudflared` из официального APT-репозитория; сам туннель нужно подключить отдельно. Для текущего развёртывания разрешён Host `remote.enactive.dev`, адрес службы `http://127.0.0.1:5187`. В Cloudflare настройте публичный маршрут `remote.enactive.dev` на этот адрес и установите службу туннеля командой из панели Cloudflare.

`ENACTIVE_LOCAL_PROXY=true` включает обработку `X-Forwarded-Proto` только от доверенных по умолчанию loopback-прокси. Не используйте этот режим с приложением, доступным в обход локального коннектора. IP клиента не переназначается: лимит входа общий для подключений через коннектор. HTTPS-порт редиректа — 443, среда — Production. `scripts/smoke-linux.py`, помещённый рядом с `app/`, проверяет запуск публикации на Linux без root, используя временную базу и порт 15187.

Проверка службы: `systemctl status enactive-server`; журнал: `sudo journalctl -u enactive-server -n 50`. Ключ входа: `sudo cat /etc/enactive-server/server.env` (не отправляйте его в чат). Для согласованной резервной копии остановите службу и сохраните весь `/var/lib/enactive-server` вместе с `/etc/enactive-server/server.env` в защищённое хранилище, затем запустите службу. Self-contained публикация включает .NET; обновления runtime требуют новой публикации приложения.

| Параметр | Значение |
|---|---|
| `ENACTIVE_OWNER_KEY` | Обязательный приватный ключ владельца длиной от 24 символов |
| `ENACTIVE_DATA` | Каталог SQLite и ключей cookie; по умолчанию `data` рядом с приложением |
| `ASPNETCORE_ENVIRONMENT` | `Development` только для локального HTTP; иначе HTTPS и Secure-cookie |
| `--urls` / настройки Kestrel | Адрес прослушивания |

`GatewayStore` хранит версионированный JSON-снимок в одной строке SQLite, изменяя его транзакционно под блокировкой процесса. Это сознательное упрощение для одного экземпляра и небольшого объёма данных, а не окончательная масштабируемая схема. При росте перейти на нормализованные таблицы, индексы и постраничные запросы. Состояние и токены не хранятся под wwwroot.

Ключи ASP.NET Data Protection сохраняются рядом с базой, чтобы сессии переживали перезапуск. Каталог должен быть доступен только учётной записи сервера. В этой версии ключи на диске отдельно не шифруются; шифрование диска/каталога и резервных копий относится к конфигурации развёртывания.

## Что ещё требуется до интернет-релиза

- Подключение настоящего Enactive Host: локальная очередь, одно выполнение на CommandId, действительные политики инструментов, проверка точного действия, восстановление после падения.
- Полноценная привязка по короткому одноразовому коду вместо ручной передачи токена; срок действия и ротация device credential.
- Внешний канал уведомлений и его надёжный outbox. Текущий Inbox не доставляет push на закрытый телефон.
- Пагинация, ограничения хранения и квоты; сейчас история растёт, снимок переписывается целиком.
- Восстановление по курсорам для больших журналов, типизированные шаги и выдача артефактов. Панель сейчас показывает последние 200 событий, последние 100 уведомлений и последнее состояние всех задач.
- Финальная модель сроков команд/разрешений и обслуживание офлайн-очереди; текущий срок 24 часа, обработка истечения при Sync Host.
- Привязка нескольких пользователей и разграничение владельцев. Сейчас инстанс строго однопользовательский; device credential не даёт доступа к API владельца.
- Проверенное production-развёртывание: DNS, TLS, разрешённые Host-заголовки, управление секретами, резервное копирование, мониторинг и restore-проверка. При reverse proxy отдельно настроить доверенные forwarded headers и WebSocket forwarding; нельзя слепо доверять заголовкам от интернета.

Ни сервер в интернете, ни DNS, ни внешний канал уведомлений этой работой не создаются. TLS здесь защищает транспорт; доверенный шлюз видит текст задачи, аргументы и результат.

# Индексация рабочих папок в Unsloth Studio

Индексация превращает подключённую папку в постоянно обновляемый источник для RAG: приложение извлекает текст, разбивает его на фрагменты, строит обычный текстовый и векторный поисковые индексы, а затем передаёт модели подходящие выдержки с указанием источников. Это помогает отвечать по большой папке без помещения всех файлов в контекст модели. Исходный код обрабатывается как текст; этот механизм не строит дерево символов или граф вызовов. [Конвейер обработки](https://github.com/unslothai/unsloth/blob/d8696f7573d5231e6af07ca0b666e2292ffed940/studio/backend/core/rag/ingestion.py#L402-L456), [обработка исходников](https://github.com/unslothai/unsloth/blob/d8696f7573d5231e6af07ca0b666e2292ffed940/studio/backend/core/rag/parsers.py#L1088-L1099).

Проверенная версия официального репозитория — `unslothai/unsloth`, commit `d8696f7573d5231e6af07ca0b666e2292ffed940`, 12 октября 2026 года. В переданной ссылке `unsloth-studio/unsloth-studio`, commit `c0851d7801f4c6e5c344030993f78c0efd5fdf75`, находятся README, assets и часть Python-библиотеки; реализации Studio там нет. Дальнейшее описание относится к каталогу `studio/` официального репозитория. [Переданный репозиторий](https://github.com/unsloth-studio/unsloth-studio/tree/c0851d7801f4c6e5c344030993f78c0efd5fdf75), [официальный исходный код Studio](https://github.com/unslothai/unsloth/tree/d8696f7573d5231e6af07ca0b666e2292ffed940/studio).

## Что происходит при подключении папки

Команда Open Folder создаёт проект и подключает выбранную папку как источник через `createLinkedFolder`. Это связывает файлы с источниками проекта. [Open Folder](https://github.com/unslothai/unsloth/blob/d8696f7573d5231e6af07ca0b666e2292ffed940/studio/frontend/src/features/chat/utils/open-folder-as-project.ts#L39-L59).

Отдельная настройка Working folder задаёт папку выполнения инструментов и сохраняется в записи проекта. Само изменение этой настройки не подключает папку к RAG; важно различать её и папку в Sources. [Настройка Working folder](https://github.com/unslothai/unsloth/blob/d8696f7573d5231e6af07ca0b666e2292ffed940/studio/frontend/src/features/chat/components/edit-project-dialog.tsx#L79-L82), [сохранение настройки](https://github.com/unslothai/unsloth/blob/d8696f7573d5231e6af07ca0b666e2292ffed940/studio/backend/storage/studio_db.py#L2967-L2989).

1. Сканер рекурсивно собирает поддерживаемые файлы и их метаданные. Он учитывает вложенные `.gitignore`, пропускает символьные ссылки, скрытые каталоги, зависимости, кэши, `.env`, lock-файлы и Terraform state. Каталоги `build`, `dist`, `vendor` и аналогичные исключаются, когда рядом есть известный manifest проекта. [Фильтры](https://github.com/unslothai/unsloth/blob/d8696f7573d5231e6af07ca0b666e2292ffed940/studio/backend/core/rag/folder_sync.py#L64-L145), [обход](https://github.com/unslothai/unsloth/blob/d8696f7573d5231e6af07ca0b666e2292ffed940/studio/backend/core/rag/folder_sync.py#L1101-L1235).
2. Новый или изменённый файл копируется в локальное хранилище RAG. Перед копированием и после него проверяются размер, время изменения и идентификатор файла, чтобы не проиндексировать смесь двух версий. [Снимок файла](https://github.com/unslothai/unsloth/blob/d8696f7573d5231e6af07ca0b666e2292ffed940/studio/backend/core/rag/folder_sync.py#L1238-L1274).
3. Парсер извлекает текст из PDF, офисных документов, HTML, Markdown и многочисленных текстовых форматов, включая исходники и конфигурацию. Для PDF конвейер предусматривает OCR и, при соответствующих настройках и доступной vision-модели, описание изображений. [Форматы](https://github.com/unslothai/unsloth/blob/d8696f7573d5231e6af07ca0b666e2292ffed940/studio/backend/core/rag/config.py#L43-L84), [обработка PDF](https://github.com/unslothai/unsloth/blob/d8696f7573d5231e6af07ca0b666e2292ffed940/studio/backend/core/rag/ingestion.py#L330-L400).
4. Текст делится на фрагменты: по умолчанию до 500 токенов с перекрытием 64 токена. Разделителями служат заголовки, абзацы, переводы строк, предложения и пробелы; сохраняются страницы и символьные смещения. [Настройки](https://github.com/unslothai/unsloth/blob/d8696f7573d5231e6af07ca0b666e2292ffed940/studio/backend/core/rag/config.py#L11-L19), [нарезка](https://github.com/unslothai/unsloth/blob/d8696f7573d5231e6af07ca0b666e2292ffed940/studio/backend/core/rag/chunking.py#L16-L30), [привязка к источнику](https://github.com/unslothai/unsloth/blob/d8696f7573d5231e6af07ca0b666e2292ffed940/studio/backend/core/rag/chunking.py#L117-L149).
5. Отдельная embedding-модель преобразует каждый фрагмент в вектор. Модель по умолчанию — `unsloth/bge-small-en-v1.5`, выбор настраивается. Тексты и векторы записываются в индексы. [Модель по умолчанию](https://github.com/unslothai/unsloth/blob/d8696f7573d5231e6af07ca0b666e2292ffed940/studio/backend/core/rag/config.py#L11-L12), [эмбеддинги и сохранение](https://github.com/unslothai/unsloth/blob/d8696f7573d5231e6af07ca0b666e2292ffed940/studio/backend/core/rag/ingestion.py#L420-L456).

## Что хранится

На каждый аккаунт выделены `rag/rag.db` и `rag/uploads/`. В uploads лежат копии документов, включая снимки файлов подключённых папок. SQLite хранит документы, фрагменты текста, поисковые индексы и состояние синхронизации. [Расположение](https://github.com/unslothai/unsloth/blob/d8696f7573d5231e6af07ca0b666e2292ffed940/studio/backend/utils/paths/storage_roots.py#L326-L338), [копирование файлов](https://github.com/unslothai/unsloth/blob/d8696f7573d5231e6af07ca0b666e2292ffed940/studio/backend/core/rag/folder_sync.py#L1238-L1274).

| Данные | Для чего нужны |
|---|---|
| Документ, область видимости, имя, SHA-256, статус, embedding-модель | Принадлежность проекту, обработка повторов и совместимость векторов |
| Текст фрагмента, номер страницы, символьные смещения, число токенов, PDF regions | Отбор контекста, цитаты и выделение места в PDF |
| `chunks_fts` на SQLite FTS5 | Поиск по словам с BM25 |
| `chunks_vec` на sqlite-vec | Поиск близких по смыслу фрагментов по cosine distance |
| Путь файла, размер, mtime, device/inode, content hash, document id | Инкрементальная синхронизация папки |

Источники: [таблицы документов и фрагментов](https://github.com/unslothai/unsloth/blob/d8696f7573d5231e6af07ca0b666e2292ffed940/studio/backend/storage/rag_db.py#L106-L140), [метаданные папок](https://github.com/unslothai/unsloth/blob/d8696f7573d5231e6af07ca0b666e2292ffed940/studio/backend/storage/rag_db.py#L163-L206), [запись двух индексов](https://github.com/unslothai/unsloth/blob/d8696f7573d5231e6af07ca0b666e2292ffed940/studio/backend/core/rag/store.py#L473-L524), [векторная таблица](https://github.com/unslothai/unsloth/blob/d8696f7573d5231e6af07ca0b666e2292ffed940/studio/backend/storage/rag_db.py#L386-L397).

## Как ищут нужные фрагменты

Поиск гибридный. FTS5/BM25 выбирает совпадения по словам; векторный поиск кодирует вопрос и находит семантически близкие фрагменты. По умолчанию берётся до 30 кандидатов из каждого канала. Reciprocal Rank Fusion объединяет позиции в двух списках по формуле `sum(1 / (60 + rank))`, где rank начинается с 1; стандартный итог — до 10 фрагментов, но вызывающая сторона может задавать другое количество. Есть также режимы только lexical или только dense. [Алгоритм и параметры](https://github.com/unslothai/unsloth/blob/d8696f7573d5231e6af07ca0b666e2292ffed940/studio/backend/core/rag/retrieval.py#L97-L153), [значения по умолчанию](https://github.com/unslothai/unsloth/blob/d8696f7573d5231e6af07ca0b666e2292ffed940/studio/backend/core/rag/config.py#L16-L19).

Таким образом, точное имя из исходника может найти текстовый поиск, а переформулированное описание задачи — векторный. Это назначение двух каналов прямо отражено в реализации: естественный язык вопроса сохраняется для embeddings, даже если lexical-часть получает отдельное выражение. Поиск ограничивается разрешёнными областями; документы с несовместимой embedding-моделью отбрасываются из dense-выдачи. [Разделение запросов](https://github.com/unslothai/unsloth/blob/d8696f7573d5231e6af07ca0b666e2292ffed940/studio/backend/core/rag/retrieval.py#L131-L146), [фильтрация векторов](https://github.com/unslothai/unsloth/blob/d8696f7573d5231e6af07ca0b666e2292ffed940/studio/backend/core/rag/store.py#L829-L936).

В интерфейсе чата собственное значение по умолчанию — 5 результатов. Его следует отличать от backend-default 10 и отдельного лимита автоподстановки 4. [Настройки UI](https://github.com/unslothai/unsloth/blob/d8696f7573d5231e6af07ca0b666e2292ffed940/studio/frontend/src/features/chat/stores/chat-runtime-store.ts#L199-L207), [лимит автоподстановки](https://github.com/unslothai/unsloth/blob/d8696f7573d5231e6af07ca0b666e2292ffed940/studio/backend/core/inference/tools.py#L14758-L14769).

## Как результаты получает модель

Модели доступен инструмент `search_knowledge_base`: она передаёт запрос и желаемое количество результатов, приложение выбирает область поиска. При явно выбранной knowledge base поиск ограничен ею; иначе объединяются документы проекта и вложения текущего чата. Идентификаторы областей скрыты от модели. Результат — фрагменты с именами файлов, страницами и отдельной картой цитат, а не только имена подходящих файлов. [Области и формат](https://github.com/unslothai/unsloth/blob/d8696f7573d5231e6af07ca0b666e2292ffed940/studio/backend/core/rag/tool.py#L53-L104), [вызов поиска](https://github.com/unslothai/unsloth/blob/d8696f7573d5231e6af07ca0b666e2292ffed940/studio/backend/core/rag/tool.py#L224-L258), [скрытая область](https://github.com/unslothai/unsloth/blob/d8696f7573d5231e6af07ca0b666e2292ffed940/studio/backend/core/inference/tools.py#L14488-L14517).

Есть и автоматический первый поиск, чтобы небольшая модель получила материалы даже без самостоятельного вызова инструмента. UI по умолчанию использует режим `auto`: он включается для моделей до 9B включительно и при неизвестном размере; доступны явные `on` и `off`. Backend ограничивает обычную автоматическую подборку четырьмя фрагментами и использует порог сходства по умолчанию 0,70. Найденный контекст вставляется как синтетический вызов `search_knowledge_base` и его результат. [Условие UI](https://github.com/unslothai/unsloth/blob/d8696f7573d5231e6af07ca0b666e2292ffed940/studio/frontend/src/features/chat/api/chat-adapter.ts#L439-L440), [разрешение режима](https://github.com/unslothai/unsloth/blob/d8696f7573d5231e6af07ca0b666e2292ffed940/studio/frontend/src/features/chat/api/chat-adapter.ts#L476-L481), [порог и лимит](https://github.com/unslothai/unsloth/blob/d8696f7573d5231e6af07ca0b666e2292ffed940/studio/backend/core/inference/tools.py#L14734-L14769), [вставка контекста](https://github.com/unslothai/unsloth/blob/d8696f7573d5231e6af07ca0b666e2292ffed940/studio/backend/core/inference/tools.py#L15275-L15284).

Модель получает инструкцию опираться на найденные документы и цитировать их. Нажатие на цитату передаёт интерфейсу document id, chunk id и страницу для открытия соответствующего места. Это даёт пользователю возможность проверить ответ по первоисточнику. [Инструкция модели](https://github.com/unslothai/unsloth/blob/d8696f7573d5231e6af07ca0b666e2292ffed940/studio/backend/routes/inference.py#L6167-L6184), [открытие цитаты](https://github.com/unslothai/unsloth/blob/d8696f7573d5231e6af07ca0b666e2292ffed940/studio/frontend/src/components/assistant-ui/tool-ui-knowledge-base.tsx#L35-L56).

## Как индекс обновляется

Автосинхронизация использует периодический обход, с ожиданием по умолчанию 30 секунд, когда очередь заданий пуста. Это не гарантия обновления каждого файла ровно через 30 секунд: обработка папок и документов также занимает время. [Очередь](https://github.com/unslothai/unsloth/blob/d8696f7573d5231e6af07ca0b666e2292ffed940/studio/backend/core/rag/folder_sync.py#L2127-L2145), [рабочий цикл](https://github.com/unslothai/unsloth/blob/d8696f7573d5231e6af07ca0b666e2292ffed940/studio/backend/core/rag/folder_sync.py#L2227-L2267), [интервал](https://github.com/unslothai/unsloth/blob/d8696f7573d5231e6af07ca0b666e2292ffed940/studio/backend/core/rag/config.py#L88-L95).

Сначала сравниваются размер, время изменения и идентификатор файла. Для новых или изменённых файлов вычисляется SHA-256 снимка. Если содержимое не поменялось, достаточно обновить метаданные. Переименование с тем же содержимым и расширением переиспользует индекс. Совпадающий документ в той же области может предоставить готовые фрагменты и векторы; rebuild принудительно повторяет обработку. Удалённые файлы удаляются из индекса. [Выявление изменений](https://github.com/unslothai/unsloth/blob/d8696f7573d5231e6af07ca0b666e2292ffed940/studio/backend/core/rag/folder_sync.py#L1670-L1705), [переименования и удаления](https://github.com/unslothai/unsloth/blob/d8696f7573d5231e6af07ca0b666e2292ffed940/studio/backend/core/rag/folder_sync.py#L1855-L1939), [переиспользование готового индекса](https://github.com/unslothai/unsloth/blob/d8696f7573d5231e6af07ca0b666e2292ffed940/studio/backend/core/rag/ingestion.py#L594-L645).

Замена индекса устанавливается транзакцией после успешной обработки нового документа; прежняя версия сохраняется, пока замена не готова. Неудачный или неполный обход не считается доказательством удаления файлов. Это позволяет продолжать поиск по последней успешно обработанной версии при временных проблемах чтения или parsing. [Установка замены](https://github.com/unslothai/unsloth/blob/d8696f7573d5231e6af07ca0b666e2292ffed940/studio/backend/core/rag/folder_sync.py#L1395-L1439), [ошибка обхода](https://github.com/unslothai/unsloth/blob/d8696f7573d5231e6af07ca0b666e2292ffed940/studio/backend/core/rag/folder_sync.py#L1649-L1668), [регрессионные проверки сохранения индекса](https://github.com/unslothai/unsloth/blob/d8696f7573d5231e6af07ca0b666e2292ffed940/studio/backend/tests/test_rag_linked_folders.py#L826-L857).

По умолчанию сканер оставляет до 10 000 поддерживаемых файлов, при количестве свыше удвоенного лимита отказывает и предлагает сузить папку. Текстовые файлы свыше 20 MiB пропускаются; общий предел файла при обработке — 200 MiB. Поэтому подключение папки не означает, что каждый её файл попал в поиск. [Лимиты](https://github.com/unslothai/unsloth/blob/d8696f7573d5231e6af07ca0b666e2292ffed940/studio/backend/core/rag/config.py#L85-L95), [применение лимитов](https://github.com/unslothai/unsloth/blob/d8696f7573d5231e6af07ca0b666e2292ffed940/studio/backend/core/rag/folder_sync.py#L1203-L1235).

## Что из этого полезно Enactive

Архитектурный вывод: такой индекс можно использовать для подготовки ограниченного контекста планировщику и исполнителю — отбирать подходящие документы и места в файлах до основного рассуждения. Общая обработка текста и документов соответствует универсальному назначению Enactive. Экономию числа чтений и токенов здесь следует считать ожидаемым эффектом, а не измеренным результатом.

При этом индекс содержит снимки и выдаёт только верхнюю часть результатов. Для точного редактирования, проверки состояния файлов и вынесения verdict нужно перечитывать актуальные файлы и опираться на журнал выполненных действий. Индекс полезен для обнаружения материала; отсутствие результата не доказывает отсутствие факта, а найденная выдержка не доказывает, что файл всё ещё находится в том же состоянии.

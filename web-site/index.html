You don't talk to the AI.
You give it a task.

Chat was right when an LLM was a clever conversationalist. Modern models plan, use tools, read files, run code and chain actions. Enactive is the environment they work in — the operating system for AI work. The model is the engine; Enactive is the workspace.

From “Chat” to “Workspace”

Four entities replace the message thread: Workspace → Tasks → Agents → Artifacts. Chat stays — as a side console, not the center.

▣

Task, not message

The primary unit of interaction is a Task with a real lifecycle: New → Planning → Executing → Waiting for user → Completed.

≡

Work state, not chain-of-thought

Structured progress — “Found 14 files → Identified bottleneck → 3 tests passed → Changes ready” — never raw reasoning.

◧

The result is the center

The agent produces an Artifact — diff, file set, dashboard, report — with [Apply] [Review] [Ask AI to improve]. Not 50 bubbles.

⚑

Decisions only at real forks

The agent runs the plan end-to-end and raises a USER DECISION REQUIRED card only when it must — with a recommended option.

One intent → real, reviewable, recorded action

Command→ Intent→ Context + Environment→ Planner→ Orchestrator→ Worker (role)→ Provider→ Tool→ Artifact→ Event→ RunRecorder

Built for agents that actually do the work

Real DAG plans

The planner emits step dependencies. The scheduler runs steps by readiness, cascade-skips dependents on failure and detects cycles.

Permissions & autonomy slider

Observe → Suggest → Execute → Autonomous. Shell and PowerShell ask before running; approvals can be remembered per session or per workspace.

Workers as roles

Developer, Reviewer (read-only), Ops, Writer — each with its own tool allowlist, permission level and model. You pick a role, not a model.

Environment awareness

Read-only discovery of host/OS, Git (branch, remote, dirty), Docker, WSL and services — fed into the prompt and shown in the UI. The agent sees “the world”.

Timeline as project memory

Not a chat history — a project timeline. Decisions and artifacts across all runs are folded into a persistent memory store.

AI Inbox & background tasks

Drop ten tasks in the evening. The agent runs headless; results and decisions land in your Inbox.

Change staging

Optional stage → diff → Apply / Reject before anything is written to disk.

Global log

Every prompt, response, tool call and event — with a raw-wire option. Live window plus a daily file.

Secrets stay local

API keys are DPAPI-encrypted in settings.json. Per-run data lives inside your workspace in .enactive/.

Autonomous by default.
Human at the fork.

The agent scans, plans, builds and tests on its own. When it hits a genuine ambiguity, it stops and asks — with options and a recommendation — instead of guessing.

A team of models, not a model picker

Configure any number of providers and bind a model to each phase of a run. Simple setups are just the degenerate case.

Plan

A reasoner turns the intent into a dependency graph and rates each step trivial / normal / complex.

Execute

Per-step auto-routing: trivial → light model, normal → the worker's own model, complex → heavy model.

Review

Each step is reviewed against the real tool transcript. On FAIL the step is retried with feedback.

Ollama (native, per-run num_ctx) Anthropic OpenAI-compatible OpenRouter · Groq · a second Ollama…

Robustness built in: local <think> off by default, Anthropic temperature auto-dropped and max_tokens auto-sized, a token-limit truncation guard, optional read-back verification of writes.

Dependency-light, open architecture

Seven projects on .NET 10. The engine — Core, Providers, Tools, Agents, Console — uses zero external NuGet packages. Only storage (SQLite / MySQL) and the Avalonia UI pull anything in.

  • Core — domain model & abstractions only: Intent, Plan/PlanStep (DAG), Worker, Decision, Permissions, Memory, Inbox.
  • Providers — OpenAI-compatible, Ollama native, Anthropic behind one factory; logging & wire tap.
  • Tools — write_file, read_file, list_dir, run_command, run_powershell.
  • Workspace — run stores (SQLite / MySQL / JSON), artifact staging, memory, inbox, environment probe.
  • Agents — Orchestrator, Planner, DagScheduler, evidence-aware Reviewer, BackgroundRunner.
  • App.Console & App.Ui — headless host and Avalonia desktop UI.

Get started in three commands

Prerequisites: .NET 10 SDK, Ollama with a tool-capable model, and optionally an Anthropic API key for multi-agent mode.

# pull a tool-capable local model
ollama pull qwen2.5-coder

# build
dotnet build

# desktop UI
dotnet run --project src/Enactive.App.Ui

# or headless: run one task, then browse the timeline / inbox
dotnet run --project src/Enactive.App.Console -- "Create a Python script that lists files" "C:\path\to\ws"
dotnet run --project src/Enactive.App.Console -- timeline "C:\path\to\ws"
